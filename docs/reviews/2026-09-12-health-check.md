## 已修复

| 问题 | 影响与修复 |
| --- | --- |
| Notion OAuth 回调输出凭据 | `/auth` 会记录客户端密钥，两个回调都会记录访问令牌，并把令牌放进跳转 URL 或页面 props。改为仅返回固定的授权结果；错误日志也不再输出可能含凭据的 Axios 对象，响应使用 `no-store`。这证明代码存在泄露路径，未读取线上密钥或日志，也未认定线上发生过泄露。 |
| 缓存清理鉴权在未配置口令时放行 | `/api/cache` 未设置 `CACHE_REVALIDATION_TOKEN` 时返回 503；错误凭据返回 401；只有正确凭据能够清理本地文件缓存。 |
| Redis 写失败被吞掉 | Redis adapter 先捕获错误、随后正常返回，导致 cache manager 误以为写入成功，不再尝试内存存储。现在让写错误传回 manager，执行原有回退。 |
| 构建缓存请求额外产生未处理的 Promise rejection | 原来单独调用 `promise.finally()` 后没有处理其返回值。将清理挂到实际返回的 Promise 链，失败可被调用者处理并重试。 |
| API 错误也报告成功 | 订阅 API 仅在 Mailchimp 接受请求时返回成功；识别未配置服务、错误邮箱和上游失败；修正姓名字段不一致，使用 API key 所属的数据中心。刷新 API 校验路径数组，部分或全部刷新失败时返回失败。 |
| `all` 刷新的描述超出实现范围 | 保留旧接口行为，明确它仅清理本地文件缓存并请求刷新首页；不再声称全站和其他实例的运行时缓存已清理。 |
| 健康脚本和 CI 检查不完整 | 构建不再被统一的 30 秒超时截断；构建/测试/质量检查失败不能被文件存在检查的分数抵消；使用与仓库锁文件一致的 Yarn 审计，审计未完成不再被断言为已发现漏洞；健康脚本和 CI 都运行两套 Worker 测试。 |

## 仍需区分的限制与后续事项

1. **文章密码是前端显示锁，不是服务端访问控制。** `resolvePostProps` 仍把正文 blockMap 放进静态 props，密码判断在客户端进行。若用于保护非公开内容，需要单独设计服务端校验与按授权取正文；本 PR 没有把这一架构问题伪装成小修补。未读取或展示受密码保护文章的内容。
2. **跨实例缓存清理尚不存在。** `/api/revalidate` 的 `all` 并不能清除其他 Serverless 实例的内存、Redis 数据或全部页面 ISR。若配置了运行时数据缓存，它仍按 TTL 生效。本次修复返回结果与错误状态，不宣称新增了完整全站刷新能力。
3. **首页首篇文章封面仍有优化空间。** “用 Codex Work 给博客做了一次装修”通过 GitHub raw 加载 1536×1024 PNG；仓库文件为 2,867,726 字节。它和已修复的 Notion attachment 封面走不同来源；本次未更换文章资产或扩大图片处理范围。
4. **GitHub Actions 未见运行记录。** 已查询当前 main 和仓库最近 workflow runs，均未返回运行记录。仓库存在 CI 配置，不能据此推定某项设置被禁用；需要在 GitHub 设置/后续 PR 检查里确认它实际执行。Vercel 构建配置跳过 ESLint，生产构建成功不能替代 CI。
5. **没有依赖漏洞结论。** 检查了依赖与锁文件配置，但当前环境未完成联网的锁文件依赖审计，没有凭版本印象升级依赖或声称依赖安全。
