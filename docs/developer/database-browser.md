# 数据库浏览与按需查询

数据库目录、数据库列表和条目正文使用独立的取数路径。普通页面不预取任何 collection query；文章发布索引及 CONFIG 表显式使用 `fetchCollections: true`，缓存键与页面内容隔离。

## 无凭据部署

数据库浏览器沿用 Notion 公开网页的匿名请求，使用 `app.notion.com/api/v3` 的页面读取、元数据同步和 `queryCollection`。不需要申请 Notion 连接或 API Key，不读取 `NOTION_DATABASE_TOKEN` / `NOTION_API_TOKEN`，不使用用户 Cookie 或官方 `/v1` 查询接口。

部署此分支即可使用，不需要新增 Vercel 环境变量。数据库本身需要公开，并且位于 `NOTION_PAGE_ID` 指定站点之下。服务端从匿名页面元数据确定 collection 和允许的 view，拒绝站点外的数据库、任意数据源及任意请求地址。访客操作只读，不修改 Notion 数据或保存视图。

纯静态导出需要单独部署 `/api/notion-database`；普通 Next.js / Vercel 部署会包含该接口。

## 加载流程

- 数据库目录只保留当前正文、子页面链接和数据库名称/视图元数据，不拉取子数据库条目。
- 数据库进入视口附近后，请求当前视图的前 30 条；点击“加载更多”后才继续。
- 搜索、筛选和排序传递为公开网页使用的 `searchQuery`、`filter` 和 `sort`，作用于当前公开视图的完整范围，不限于已加载条目。
- 保留保存视图的完整 AND/OR 条件和属性快捷筛选，再叠加访客条件；访客排序覆盖默认排序。重置后恢复保存视图。
- 查询本身返回条目属性，不读取条目正文；仅在本批属性缺失时补一次匿名批量读取。响应只保留本批公开条目的展示属性和必要图片信息，剔除正文及无关记录。
- 匹配数通过 count reducer 读取。不能把 `sizeHint` 当作筛选后的总数：实测搜索匹配 1 条时，该字段仍是全库的 1,576。
- 限流、超时、最多 100 项的 60 秒内存缓存、并发请求合并控制上游开销；这些查询不写 ISR 页面缓存。

### 公开接口的增量加载限制

实测 `queryCollection` 忽略 `offset`，没有在响应中提供稳定分页游标。实现使用明确的渐进上限：30、60、90……；服务端会重新读取请求范围，只将新增的最多 30 条返回给浏览器。不会自动请求完整数据库，不会假装这是原生游标分页。

继续加载参数包含查询指纹、已读取 ID 序列的摘要和过期时间。每次重新验证匿名权限、数据库归属、视图和数量边界。它不是认证凭据，不需要密钥；任意伪造参数也不能扩大公开权限或绕过单次请求上限。之前范围发生插入、删除或重排时要求刷新，避免静默重复或遗漏。返回值更新而 ID 顺序未变时，已显示属性可能保留旧值，重新进入或刷新后更新；公开接口不提供一致性快照。

单次公开查询最多扩展到 10,000 条；上游提前截断或到达这个上限时明确提示缩小筛选范围/查看原页，不把截断当作“已全部加载”。大库逐批浏览的上游成本随已加载范围增加；搜索和筛选可以先缩小范围。

## 展示与导航

- 正文中的站内页面链接使用 Next.js 客户端导航（关闭视口预取），不再等待整个 HTML 返回后才换页。Medium 在 `routeChangeStart` 立即隐藏旧正文，显示目标链接标题和骨架屏；blocks/元数据就绪后交给数据库自身的前 30 条加载状态。Pages Router 的地址栏仍在路由提交时更新，不手动改写历史记录。
- 浅路由筛选和同页锚点不触发整页占位；导航失败/取消恢复旧内容、焦点和滚动位置，旧导航的迟到事件不会清除新导航的占位。
- 表格、画廊、列表、看板共用查询结果，看板的分组计数注明“已加载”；其他布局提供原页入口。
- 不支持的日历、时间轴等视图不会请求条目，也不显示查询/加载更多控件；切走时取消进行中的请求。
- 表格恢复原生列布局，隔离旧全局 simple-table 样式。列宽不随总列数压缩，容器内横向滚动，提供左右滑动提示和方向按钮。文字默认换行，可切换单行；单列宽度最多占一个可视区域，手机不固定首列，桌面固定首个标题列。
- 返回当前批次属性引用的公开用户姓名/头像、关联页面标题/图标、关联数据库名称等元数据，分页追加和上下文合并保留这些记录；不带关联页正文、无关记录或邮箱等字段。
- 日期条件使用经服务端校验的浏览器时区；无时区时采用 UTC。时区参与服务端缓存、继续加载指纹和浏览器恢复缓存，跨时区不能混用分页状态。
- 查询状态写入带数据库 ID 的 URL 参数，一个页面可独立使用多个数据库。
- 浏览器短期保留已加载结果及滚动位置；返回列表时恢复。禁用存储也可浏览。
- 快速切换条件时取消旧请求并丢弃迟到响应。查询失效、上游限流和网络失败均提供恢复入口。
- 条目链接关闭自动预取；点击后按需加载正文和数据库属性。

## 实际公开请求验证（2026-09-18）

- 使用改造后的无凭据服务直接查询三个数据库：技能 1,576 条、支援卡 429 条、角色 194 条。首批和第二批均为 30 条，互不重复。
- 技能名称 `コネクト` 搜索返回 1 条，总数也为 1；稀有度“稀有”返回总数 247；技能持续时间大于 0 并降序返回总数 1,265。
- 数值等于 13 返回 2 条，不等于 13 返回 1,574 条；复选框、文本和日期条件也经匿名请求验证。
- 单独验证公开接口上限 1,590 时返回全部 1,576 个唯一 ID，`hasMore=false`，前 60 条顺序与早先请求一致。此为边界验证，正常首屏仍仅请求 30 条。
- 目录正文裁剪后保留 7 个块，约 28 KB；不会携带数据库条目查询结果。
- 仓库全量 lint 的既有问题位于未修改的 `bookmarkImages.mjs` / `writingMode.mjs`。部署预览验收结果见 PR。
- 改造后全量 Jest：88 个套件、520 项通过；改动文件 ESLint 和 TypeScript 检查通过；Next.js 生产编译通过（compile 模式）。
